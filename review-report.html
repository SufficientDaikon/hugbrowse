🔴 CRITICAL — FR-013: Download State Lost on App Restart
The DownloadManagerState is an Arc<Mutex<HashMap>> held entirely in memory. When the app restarts, every download entry (in-progress, paused, completed, failed) is gone. The .part file survives on disk, but the panel shows no entries. Users cannot resume an interrupted download without manually re-initiating it from the model detail page. US2 acceptance scenario 2 ("close and reopen → resume from byte offset") fails at the UX level.
src-tauri/src/download.rs:53-65 · src-tauri/src/lib.rs:283
Fix: On every state change in do_download (after each emit_progress call), serialize DownloadManagerState.downloads to a JSON file in app_local_data_dir() (e.g., downloads.json). On startup, deserialize and restore completed/paused entries. Active (Downloading) entries should be re-marked as Paused on restore. The tauri-plugin-store is already in Cargo.toml and can be used for this.
🟠 MAJOR — FR-045/046: System Tray Entirely Missing
Neither tauri-plugin-notification nor any tray plugin is added to Cargo.toml. The on_window_event(Destroyed) handler kills llama-server rather than persisting it to tray. Closing the window while a model is running terminates inference (opposite of FR-045). No tray icon, no tray context menu (FR-046). This blocks US8 acceptance scenarios 2, 3.
src-tauri/src/lib.rs:306-311 · src-tauri/Cargo.toml (tray plugin absent)
Fix: Add tauri-plugin-tray = "2" to Cargo.toml. Change on_window_event(Destroyed) to check if a model is running; if so, hide the window instead of destroying it (use window.hide() and intercept CloseRequested). Register a tray icon in lib.rs with a context menu: Open, Quick Chat, Stop [Model], Quit.
🟠 MAJOR — NFR-009: No llama-server Crash Detection
The spec requires crash detection within 2 seconds and a one-click "Reload Model" option. After load_model succeeds, the health endpoint is never polled again. If llama-server crashes mid-chat (OOM, bad GGUF, GPU driver error), the UI shows "Running" until the next sendMessage call fails with a fetch error — up to minutes later. No "Reload Model" button is shown in the error state.
src-tauri/src/inference.rs · src/stores/inference.ts · src/pages/ChatPage.tsx
Fix: Start a background polling loop after successful load (every 2s, poll /health). If the endpoint stops responding for 2 consecutive polls, emit a Tauri event (inference-crashed) and set status to Error. In ChatPage.tsx, render a "Reload Model" button when info.status === 'error'.
🟠 MAJOR — FR-041/042/043: MCP Tool Dispatch Not Implemented
While mcp.ts defines the tool discovery mechanism and data types correctly, the entire tool-dispatch pipeline is absent: (1) sendMessage in chat.ts has no logic to detect tool-call JSON blocks in the SSE stream; (2) there is no callTool function in mcp.ts; (3) no 30-second timeout exists; (4) no "Tool Call" badge component exists. This means US7 is effectively non-functional beyond tool listing.
src/stores/chat.ts:sendMessage · src/stores/mcp.ts · src/components/chat/
Fix (P3 — can ship without): In the SSE loop of sendMessage, detect finish_reason: "tool_calls" in the final delta. Extract the tool call, call mcp.discoverTools(serverId) to find the right server, POST to {server.url}/tools/call with a 30s AbortSignal. Inject the tool result as a role: "tool" message and continue the chat loop.
🟡 MINOR — FR-011: Disk Space Enforcement Not in Rust Command
SpaceCheck.tsx shows a warning when free space < modelSizeGb * 1 and "plenty" at modelSizeGb * 2. The spec requires a blocking rejection at 1.2×. The actual start_download Tauri command (download.rs:315) performs no disk check — it proceeds unconditionally. A determined user can bypass the UI warning and start a download that will fail mid-way due to disk full.
src-tauri/src/download.rs:315 · src/components/download/SpaceCheck.tsx:27
Fix: In start_download (before inserting the entry), call check_disk_space(dest_dir) and return an Err if free_gb * 1_073_741_824.0 < total_bytes as f64 * 1.2. Also update SpaceCheck.tsx threshold from * 2 to * 1.2 to match the spec.
🟡 MINOR — FR-017: Unload Uses SIGKILL Immediately (No SIGTERM Grace Period)
The spec requires SIGTERM → wait 5 s → SIGKILL. The implementation calls child.kill() immediately in both unload_model and on_window_event. This prevents llama-server from flushing any in-flight responses or saving state gracefully, and may leave temporary files on disk.
src-tauri/src/inference.rs:130 · src-tauri/src/lib.rs:310
Fix: Use tauri_plugin_shell::process::CommandChild::signal(Signal::Term) (if available), then tokio::time::timeout(5s, child.wait()), then fall back to child.kill(). On Windows, graceful termination is via GenerateConsoleCtrlEvent — Tauri's shell plugin may handle this automatically.
🟡 MINOR — FR-047/048: Updater Plugin Wired but Will Crash at Runtime
tauri-plugin-updater is registered in lib.rs:293. Without a pubkey and endpoints in tauri.conf.json, the plugin panics or silently fails on first update check. Additionally, no TypeScript code calls check() from @tauri-apps/plugin-updater, so no update check is ever triggered from the JS side.
src-tauri/src/lib.rs:293 · src-tauri/tauri.conf.json (plugins.updater absent)
Fix (before production): Either add a placeholder updater config with a real endpoint, or guard the updater plugin behind a compile-time feature flag so dev builds don't fail. Add a TypeScript call to check() in App.tsx on mount, displaying a toast notification when an update is available.
🟡 MINOR — Default API Port is 8080, Spec Requires 11434
ModelRunPanel.tsx:23 defaults to port 8080. The spec (FR-028) and US5 acceptance scenario 1 specify default 11434 (matching Ollama's port, making it a drop-in replacement). This affects out-of-the-box curl/SDK examples and documentation consistency.
src/components/models/ModelRunPanel.tsx:23
Fix: Change useState(8080) to useState(11434). Update any hardcoded port references in documentation/onboarding copy.
