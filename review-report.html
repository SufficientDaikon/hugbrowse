🔍 Key Findings

Strengths

✅ Rock-solid download manager — Full resume via HTTP Range headers, SHA-256 verification, disk space checks (1.2×), persistence across restarts, concurrent downloads with independent progress. Production-quality implementation.
✅ Well-architected inference layer — Sidecar management with port collision detection (EC-002), health polling, graceful shutdown (POST /shutdown → 5s grace → kill), orphan prevention on both load and window destroy.
✅ Security best practices — HF token in Tauri encrypted store (NFR-007), excluded from localStorage via partialize; CSP properly configured (NFR-008); llama-server binds 127.0.0.1 only (NFR-006).
✅ Complete chat experience — SSE streaming, tok/s tracking, markdown with syntax-highlighted code blocks + copy button, session CRUD, history persistence, abort support.
✅ RAG engine implemented — rag-engine.ts with chunking, BM25-like retrieval, context building with source citations. Properly integrated into chat flow.

Issues Requiring Attention

❌ No llama-server binary checksum (FR-020, EC-003) — Spec requires verifying sidecar binary integrity on first launch and updates. Security concern: corrupted/tampered binary could execute arbitrary code.
❌ Auto-update not implemented (FR-048, EC-018) — Plugin registered but no checking logic, download progress, or user prompt. Important for production deployment.
❌ Multi-GPU not supported (EC-007) — Only first GPU detected. Users with multiple GPUs cannot select which one to use for offloading.
⚠️ Crash detection too slow (NFR-009) — Health poller: 10s interval, 3-strike rule = 30s worst case. Spec requires 2s detection. Reduce interval + immediate detection needed.
⚠️ RAG: PDF/DOCX not actually parsed (FR-034) — readFileAsText() uses FileReader which doesn't extract text from binary formats. Needs pdf.js for PDF, mammoth for DOCX.
⚠️ Context overflow is silent (EC-010) — Auto-truncates without warning. Spec requires user notification with summarize/truncate options.
⚠️ MCP tool calling not wired into chat (FR-041, FR-043) — MCP client can call tools but auto-detection of tool-call JSON in model output and re-injection not integrated into streaming chat flow.
⚠️ Tray menu incomplete (FR-046) — Has "Show" and "Quit". Missing "Quick Chat" and "Stop [Model Name]" items specified by the spec.
