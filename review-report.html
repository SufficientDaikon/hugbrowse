1. Executive Summary

HugBrowse delivers a solid foundation as a local AI desktop application. Phases 1–3 (Tauri build, download manager, llama-server sidecar) are fully implemented with proper persistence, resumable downloads, SHA-256 verification, disk space guards, port collision detection, health polling, and graceful shutdown. Phase 4 (Chat) is strong: SSE streaming, markdown rendering, session management, system prompts, and tok/s display all work. Phase 5 (Local API) leverages llama-server’s native OpenAI-compatible endpoints effectively.

The primary gaps are in Phase 6 (RAG) — only a store skeleton exists with no actual document processing, chunking, or embedding — and Phase 8 (Polish) — the tray menu is minimal (missing Quick Chat / Stop Model), window close kills the model instead of minimizing to tray, and auto-update has no UI. Phase 7 (MCP) has good client infrastructure (timeouts, defensive JSON) but isn’t wired into the chat tool-calling flow.

6. Findings by Severity

🔴 High Severity (Blocking)

HIGH FR-035, FR-036, FR-037, SC-009
RAG pipeline is not implemented. The rag.ts store has document CRUD operations and empty-document rejection, but there is no file reading, text extraction (PDF/DOCX), chunking, embedding, vector storage, or retrieval. The entire Phase 6 semantic search pipeline is missing. This is a P2 feature that blocks SC-009.
HIGH FR-045
Window close kills the inference engine instead of minimizing to tray. The on_window_event(Destroyed) handler immediately kills the llama-server child process. Spec requires the app to minimize to tray and keep the model running when the window is closed. This is user-hostile for anyone running long inference tasks.
HIGH FR-032
API server does not auto-start on launch. No logic persists the “model was loaded” state or auto-loads the model on next startup. Users must manually load the model every session, breaking developer workflow (e.g., scripts that depend on the local API being available after reboot).

🟠 Medium Severity

MEDIUM FR-046
System tray menu is incomplete. Only “Show HugBrowse” and “Quit” are present. Spec requires “Open”, “Quick Chat”, “Stop [Model Name]”, and “Quit”. The Quick Chat and Stop Model entries are missing.
MEDIUM FR-041, FR-043
MCP tool calling not wired into chat. callTool() infrastructure exists with proper timeout and error handling, but the chat store’s sendMessage() never parses model output for tool-call JSON blocks, never dispatches to MCP, and never injects results. No “Tool Call” badge component exists.
MEDIUM NFR-009
Crash detection is too slow. The health poller runs every 10 seconds with a 3-failure threshold, meaning ~30 seconds to detect a crash. Spec requires ≤ 2 seconds. Additionally, no “Reload Model” button is offered on crash — only an error message is shown.
MEDIUM FR-022
Code blocks lack true syntax highlighting. The CodeBlock component renders code in a monospace font with a copy button, but does not integrate a syntax highlighter (Prism, Highlight.js, or Shiki). The spec requires “fenced code blocks with syntax highlighting”.
MEDIUM FR-020, EC-003
No sidecar binary integrity verification. The llama-server binary is never checksummed. A truncated or corrupted binary would produce a confusing spawn error rather than a clear “binary is invalid, re-download” message.
MEDIUM EC-007
No multi-GPU support. On systems with 2+ GPUs, there is no enumeration or selection UI. The --n-gpu-layers flag is passed but GPU selection (which GPU to offload to) is not exposed.

🔵 Low Severity

LOW FR-027
Context usage counter not shown in UI. The tok/s metric is displayed during and after streaming (well done), but a “tokens used / context limit” indicator is not visible. The spec calls for both.
LOW FR-031
No HTTP 503 when no model is loaded. When llama-server isn’t running, API clients get a connection refused error rather than a structured {"error": "no_model_loaded"} response. Consider a lightweight proxy or error handler.
LOW FR-039
MCP server URL is hardcoded. The spec requires users to configure one or more MCP server URLs. The current implementation only connects to HuggingFace’s MCP server at a hardcoded URL.
LOW NFR-004
OOM warning not enforced before loading. check_compatibility exists and provides memory warnings on the model detail page, but it is not shown as a gate before the “Load Model” action in ModelRunPanel.
LOW EC-001
Corrupted GGUF shows error but no re-download offer. When llama-server rejects an invalid GGUF, the error is surfaced, but there’s no “Re-download” action button to make recovery easy.

7. What’s Working Well 👏

  • ✓ Download Manager — Best-in-class: resumable with Range headers, .part files, SHA-256 validation, disk space guard (1.2×), pause/resume via atomic flags, concurrent downloads, crash-safe persistence.
  • ✓ Inference Sidecar — Port collision detection, graceful SIGTERM→SIGKILL shutdown, health polling, 127.0.0.1 binding, orphan process prevention.
  • ✓ Security — HF token properly excluded from localStorage, stored in encrypted Tauri store, CSP is tight and correct.
  • ✓ Chat Experience — SSE streaming with real-time tok/s tracking, markdown rendering, session management with persistence, system prompts, abort support.
  • ✓ Edge Case Handling — Deleted files detected, rate limiting with exponential backoff, context overflow guard, empty RAG document rejection, MCP defensive JSON parsing.
  • ✓ Onboarding — Clean 4-step wizard with hardware detection and skip option.

8. Recommendations

Must Fix (to reach APPROVED WITH CONDITIONS)

  1. Implement RAG pipeline (FR-034–037): Add file reading (PDF via pdf.js, DOCX via mammoth), text chunking (512-token, 64-overlap), embedding via llama-server’s /embedding endpoint, vector storage, and top-K retrieval injected into chat context.
  2. Minimize to tray on close (FR-045): Intercept CloseRequested event instead of Destroyed. If a model is running, call window.hide() and prevent default close. Only kill on explicit “Quit” from tray menu.
  3. Auto-start API server (FR-032): Persist last-loaded model path in the Tauri store. On startup, if a model was previously loaded, auto-load it.
  4. Complete tray menu (FR-046): Add “Quick Chat” (show window + navigate to /chat), “Stop [Model Name]” (unload model), update tooltip to show running model name.
  5. Wire MCP into chat (FR-041, FR-043): In the SSE streaming loop, detect tool-call JSON blocks from the model, dispatch to mcpClient.callTool(), and inject the result as a tool message. Add a “Tool Call” badge component.

Should Fix

  1. Add syntax highlighting (FR-022): Integrate react-syntax-highlighter with Prism into the CodeBlock component.
  2. Speed up crash detection (NFR-009): Reduce health poll interval to 1s or use process exit detection via Tauri shell events. Add a “Reload Model” button in the error state.
  3. Sidecar checksum (FR-020, EC-003): Compute SHA-256 of the llama-server binary on first launch; store in config. Check on subsequent launches.
  4. Context usage counter (FR-027): Add a “tokens used / context limit” indicator next to the tok/s display or in the right sidebar.
  5. Multi-GPU selection (EC-007): Enumerate GPUs via nvidia-smi on Windows/Linux; let user choose which GPU to offload to in ModelRunPanel.

Nice to Have

  1. HTTP 503 proxy (FR-031): Add a minimal proxy or middleware that returns a proper 503 JSON body when no model is loaded.
  2. MCP server URL configuration (FR-039): Add a text input in Settings to configure custom MCP server URLs.
  3. OOM gate before load (NFR-004): Show the compatibility check result as a warning/confirmation dialog before proceeding with model load.
  4. Re-download action (EC-001): On corrupted GGUF error, add a button to delete and re-download the file.
  5. Auto-update notification UI (FR-047, FR-048): Surface Tauri updater events as a non-blocking toast in the app.
